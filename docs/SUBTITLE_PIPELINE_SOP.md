# yqxyy 字幕流水线 SOP v1.1

## 职责纠偏（2026-11-06，优先于下方旧表述）

- **ChatGPT 是实际后处理执行者，不只是编排者**：在当前对话/可执行环境中亲自读取官方 XML 与已保存的识别结果，完成字幕校对、估算缺失词时间、剥离 Little Fox 格式标记、生成 VTT 和 words.json、运行质量验证，形成可提交的最终文件。不得将这些职责默认转交给 GitHub Actions。
- **GitHub 是代码/产物仓库**：接收 ChatGPT 已完成并验收的字幕文件、审计报告和提交记录；可以执行轻量 CI 校验，但不得作为默认字幕后处理工人。
- **计算环境只负责无法在对话环境完成的重型任务**：例如首次 WhisperX 语音识别，保留可复用原始结果。若因工具或数据不可用而无法在对话环境完成，必须说明具体阻塞，不能假装已经亲自处理。
- **Netlify 负责部署**；ChatGPT 负责核实线上结果，不能以 GitHub 提交代替上线验收。
- **后台监督与前台执行分开**：定时监督任务只负责检查、通知和在工具允许时进行明确可验证的操作；不得声称当前聊天模型会在没有自动任务/工作流的情况下持续后台运行。
- **每批次证据链**：ChatGPT 处理记录 → 本地/对话验收 → GitHub 提交 SHA → Netlify 部署证据 → 中文成果报告。旧 GitHub 后处理工作流仅作历史兼容/应急，不作为新批次默认路径。



生效范围：Little Fox 英语学习视频；默认批次 3 集，验证稳定后扩大。负责人：ChatGPT（编排、质量审核、进度汇报），GitHub（版本管理及必要的重型计算），Netlify（网站部署）。

## 分工与交接

| 阶段 | 责任方 | 输入 | 输出 | 完成条件 |
|---|---|---|---|---|
| 1 选集与查重 | ChatGPT | episodes.json、已有字幕 | manifest（剧集编号、标题、content ID） | 不重复处理、连续批次 |
| 2 素材获取 | ChatGPT/可用云端工具 | 官方 XML、合法可访问视频音轨 | 原始 XML、音频及来源记录 | XML 内容 ID 对应视频 |
| 3 首次语音识别 | GitHub Actions 或可用云端计算环境 | 音频、官方文本 | WhisperX 原始逐词时间、日志 | 识别产物可复用，失败保留审计材料 |
| 4 校正与生成 | ChatGPT | XML + 原始时间戳 | .vtt、.words.json | 仅官方 XML Text 决定显示文本；去除 [g@] [i@] 等格式控制符；错词以 XML 修正；缺时词估算且 source=estimated |
| 5 自动验收 | ChatGPT + 脚本 | 生成文件 | QA JSON | 真实匹配率≥90%；估算不计入真实匹配；无异常长词、逆序、明显跨句错位；字幕文本与清理后的 XML 一致 |
| 6 发布 | GitHub | 已验收文件 | commit SHA、发布报告 | VTT/words JSON 成对提交，报告记录每集指标 |
| 7 部署验证 | Netlify + ChatGPT | GitHub commit | 网站可用性结果 | 确认部署成功、播放与高亮可用；不能验证时标记待验证 |
| 8 汇报 | ChatGPT/定时监控 | GitHub Actions、提交、报告、部署证据 | 中文进度简报 | 列出已完成/失败/待处理、具体集数、质量、链接 |

## 质量门槛与例外

1. 官方 XML 的 Text 是唯一显示文本来源；格式标记应解析/剥离，不得露出 `[g@`、`[i@` 等。
2. 已验证的真实时间戳不应因估算而覆盖；无法可靠识别的单词只用邻近锚点推算，标记 `source=estimated`。
3. 每集真实时间匹配率至少 90%；若低于门槛、音频/字幕不匹配或明显错位，则不自动发布，进入复核。
4. 生成文件必须覆盖全部官方文字，VTT 与 words.json 句子文本一致，时间戳为有效非负数，单词和字幕段落时序合理。
5. 每个批次必须有独立报告：剧集编号、真实匹配率、估算词数、错误原因、提交 SHA、部署核验结果。不能把“已提交 GitHub”等同于“网站已上线”。
6. 避免重复跑 WhisperX：已有原始结果优先后处理；重型识别仅在素材新增或质量不达标时执行。
7. 禁止因某一集失败阻断其他已达标剧集；逐集记录状态并可重试。

## 状态定义

- 待处理：尚未获得素材
- 识别中：运行音频识别
- 待后处理：已有原始识别数据
- 待验收：已生成候选文件
- 已提交：文件已进入 GitHub
- 已上线：Netlify 部署及网页功能验证通过
- 失败/需复核：记录明确原因与下一步

## 进度汇报格式

批次：系列/集数；总数 N；已上线 N；已提交 N；待处理 N；失败 N。
每集：中文/英文标题、真实匹配率、估算词数、状态。
附 GitHub 提交与运行链接，报告最新阻塞和解决动作。
